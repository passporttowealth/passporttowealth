# Changelog

> **⚠ Prototype — pre-release.** Versions in the `0.x.y` range are pre-release. Treat any update as potentially breaking until the project reaches `1.0.0`.

All notable changes to this repository will be documented here. The skill self-update flow reads from this file (and the matching GitHub Releases) to decide whether to prompt clients to update.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow [SemVer](https://semver.org/).

## [Unreleased]

- **Landing page redesigned (egregore-style) + START-HERE removed + short URL via shim (B9.10).** The landing page at `https://passporttowealth.app/` is now a single-page product site with the curl one-liner as the primary CTA + copy button. OS-toggle (Mac/Windows), navy/white minimalism, no download buttons. Install command shortened from `curl -fsSL https://raw.githubusercontent.com/passporttowealth/passporttowealth/main/installer/install.sh | bash` to `curl -fsSL https://passporttowealth.app/install | bash` via a tiny shim that exec-fetches the canonical script — single source of truth on GitHub, brandable URL on the landing page. **START-HERE.command and the workspace launcher are gone**: re-entry is `claude` from any Terminal. The skill scripts default `PYTHON` to the workspace venv so they run from any cwd; for API-key auth, `ANTHROPIC_API_KEY` gets exported to the user's shell rc by the installer (idempotent block) so `claude` finds it. Net: zero artifacts on the user's Desktop or laptop besides `~/Documents/my-finances/` itself. Curl-pipe-bash gotcha fixed: install.sh now does `exec </dev/tty` so consent prompts actually receive user input under `curl ... | bash`.
- **Local-first by default; sharing is opt-in (Strategic #2).** Step 4 ("publishing-host signup") removed from the installer entirely. After every refresh, `view-local.sh` opens `$WS/site/index.html` in the user's default browser via `file://` — no third-party server, no signup, no passcode (the OS lock screen already gates access). The publishing-host email-code signup that used to live in the installer has moved to `skill/scripts/publish.sh` and runs only when the user explicitly chooses to share their dashboard with an advisor or family. **Users who never share never sign up — the dashboard stays purely local for them.** Installer is now Step 1-of-5 instead of 1-of-6. Spec §4.4 rewritten, new §12.7 documents the local view, §13 reframed as opt-in. Demo script Phase 3 ends with local view; Phase 4 is now "Share it (optional)".
- **Installer: uv migration** — Step 2 now uses `uv` (Astral's single-binary Python toolchain) for managed-Python install, venv creation, and dep resolution. Replaces the previous `Homebrew → brew install python@3.11 → python -m venv → pip install` chain (four prompts/operations) with one binary download + three uv invocations. Side effect: Homebrew is now conditional — only invoked if `jq` is missing, since uv replaces every other use. Diagnostic checks `uv` instead of brew; PYTHON311 now resolves via `uv python find 3.11` (always an absolute path inside uv's managed install dir, fixes the dry-run "Python 3.11 installed ✗" false-positive structurally).
- **Installer dry-run fixes (Issues A–E):** opening text now paces section-by-section with Press-Enter gates (Issue A); stale "v0 skeleton" / "engagement/development/" comments removed (Issue B); FX pre-warm progress bar streams to /dev/tty so it actually shows during install (Issue C); Python 3.11 diagnostic resolves to absolute path so it doesn't false-positive (Issue D); diagnostic failures no longer dead-end the install if the workspace launcher is in place — they demote to a warning so the seamless handoff continues (Issue E1); auto-closes the Terminal window after a 5s countdown on the no-handoff exit paths (Issue E2); SIGINT/SIGTERM trap logs which step the user cancelled at and exits with conventional code 130 (Issue E3).
- **Landing page now live at `https://passporttowealth.app/`** (apex; `www.` 301s to it). Deployed to here.now (slug `sandy-delta-dc3r`) via the here-now skill instead of GitHub Pages. Download buttons now use relative URLs (`Welcome.command`, `Welcome.bat`, `Welcome.ps1`) served from the same here.now bundle — removes the dependency on `raw.githubusercontent.com` and means the GitHub repo no longer has to stay public for the installer to be reachable. The `.github/workflows/pages.yml` workflow still ships a backup mirror to GitHub Pages on every push to `main`. Docs updated: README, installer/README, docs/advisor-onboarding, dev/github-repo-layout, dev/finance-clarity-build-spec.
